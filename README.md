# defi-yield-optimizer

複数チェーン/プロトコルの利回り(APY)を横断的に比較し、資金配分を最適化するツール。

## 進め方(段階を踏む)

1. **フェーズ1(今ここ)**: DeFiLlama公開API(`yields.llama.fi`)から読み取り専用でAPYデータを取得・分析。
   ウォレット接続や送金は一切行わない。まずはどのプール/チェーンが安定して高利回りかを
   データで把握する。
2. **フェーズ2**: 過去のAPY推移データを蓄積し、変動リスク(APYの安定性、TVLの増減、
   プロトコルの監査状況)を加味したスコアリングモデルを作る。
3. **フェーズ3**: 実際の資金移動・スマートコントラクト操作(入金/出金/スワップ)は
   ユーザー自身のウォレットで実行する。自動化する場合も、まずテストネットや少額での
   検証を挟むこと。秘密鍵はどのコードにもハードコードしない。

## セットアップ

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
python src/yields.py     # 全プールのAPYスナップショット
python src/scoring.py    # 上位候補の履歴を取得し、安定性を加味してスコアリング
```

`notebooks/explore_yields.ipynb` を開く場合は、先に `.venv` をJupyterカーネルとして登録すること
(グローバルのPython環境には依存パッケージが入っていないため、既定のカーネルのままだと動かない)。

```bash
.venv/Scripts/python -m ipykernel install --user --name defi-yield-optimizer --display-name "Python (defi-yield-optimizer)"
```

`src/scoring.py` は生APYの平均ではなく中央値を使い、変動係数(apy_cv)が高すぎる
(閾値1.0超)プールはスコア対象から除外する。異常に高いAPYは大抵、報酬トークンの
一時的な大量エミッションや薄い流動性による見せかけであり、そのまま鵜呑みにしない
ための安全弁。

## 注意

- スマートコントラクトリスク、ステーブルコインのデペッグリスク、プロトコルのハッキングリスクは
  常に存在する。TVLが極端に低い/新しすぎるプロトコルの異常に高いAPYは要注意。
- 秘密鍵・シードフレーズは `.env` にも書かない。ウォレット操作が必要な段階になったら
  ハードウェアウォレットや個別の安全な鍵管理を検討する。
